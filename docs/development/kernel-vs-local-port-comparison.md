# 内核端点与本地 Node port：完整功能差异及日常影响

核对日期：2026-09-29。基于当前未提交工作区、第五批插件优化及余项补验后的超时修复构建；静态清单来自 TOOL_CATEGORIES / ACTIONS_BY_CATEGORY，14 类、143 个 action，另加各类 help、动态扩展、MCP App 及传输/运行时能力。

**当前结论：143 个静态 action 均有实现；其中 5 个存在内核专属的部分限制（√），其余 138 个未发现 action 级专属缺失（X）。** 5 个受限 action 对应附件上传、创建/更新超大模板、ZIP 导出和文档提取，并非这 5 个功能完全不可用。通用读取预算、宿主请求中断和接入方式另外列出，不能用“138 个 X”推导任意数据规模、任意客户端都与 Node 完全等价。

这里的“本地 port”指 **Node HTTP MCP 服务自行执行**；Node 所在机器可能是用户电脑，也可能是远程服务器。启用 kernel owner 后，Node/CLI 的严格修改和选定文件导出会委托内核；普通读取仍可在 Node 执行。因此“通过本地 port 访问”不等于所有业务都由 Node 执行；委托内核的调用同样受内核限制。不得把临时切换 owner 当成失败重试方式。

“支持/无专属缺失”是源码路径结论，不表示全部 action 均做过真实环境验收。最新已完成的 1380 项自动化测试、容器补验及未实测清单见 [验收记录](kernel-endpoint-verification.md)。本次仅整理对照文档，沿用已完成的测试结果；不将文档更新描述为重跑业务测试。全部改动限于插件，在隔离容器验收；思源核心和个人笔记未修改。反馈新增临时容器插件到受控接收器的 GET/POST 与失败不重试验证；遥测通过原版容器代理向受控本地 HTTP 服务发送及失败冷却验证，未向真实外部服务提交测试数据。高级选项与剩余边界见 [内核配置](../zh/reference/kernel-options.md)。

## “是否缺失”判定口径

- **√：内核相对本地 port 缺少该行能力，或只支持其一部分。** 若 CLI/Node 桥接可以补齐，会在同一行说明。
- **X：未发现该行功能缺失。** 可以存在性能、覆盖策略、确认方式或接入步骤差异；这些不自动算功能丢失。
- 普通读取 action 标 X 表示该 action 已实现；“超预算的一次性大范围读取”单独标 √，不把所有读取 action 都误报为缺失。图片专用预算已补齐；超大模板仍有正文上限，标 √。
- 双方都没有的功能标 X，并注明“双方共同不足”：这里比较的是内核相对本地 port 的缺失，不表示该能力已经实现。
- X 不是“所有真实场景已测通过”；待验证项与实测范围仍保留。MCP App 声明已补齐；跨客户端显示仍需要对应客户端实测。

## 测试证据如何理解

本次补验提升了验证覆盖，但没有消除宿主能力和大小限制，因此仍为 **5 个静态 action 部分受限、138 个未发现 action 级专属缺失**。下表新增“测试情况”列，与“是否缺失”独立判定。

- **容器实测**：真实思源容器、原版构建产物和实际 API；仅表示列出的场景通过。
- **受控故障**：真实容器配合临时插件宿主边界或 HTTP 故障代理；接收器/代理制造错误并统计调用次数，不是生产外部服务认证。
- **受控浏览器 Host**：真实浏览器加载生产 HTML，通过测试 Host 转发到容器；不是所有实际 MCP 客户端兼容性验收。
- **前批容器**：沿用前批已记录场景，不冒充最后一次构建逐项重跑。
- **源码/自动化**：实现已核对或公共链路有自动化覆盖，不能替代该 action 的真实执行。未逐项实测不自动标为功能缺失。

## √ 缺失或部分受限：优先关注

所有 √ 项集中放在前面，X 项统一放在后面。以下是插件优化及余项补验完成后的剩余差异，按日常影响排列；概览和 action 表存在对应关系，不能把行数相加当成独立缺陷数。共 191 行比较：15 行 √、176 行 X；这是展示行数，不是缺陷数。

- **继续关注**：大范围读取、协作式期限、宿主响应缓冲与直连文件保存。已提供分页、重试、预算配置及桥接；宿主原生中断/流式接口仍缺少支持。
- **已经补齐的插件缺口**：图片专用预算、App 声明、反馈/遥测网络适配、Skills 开关和插件 Origin 白名单，移至 X 区域。
- **保留限制**：附件硬上限 10 MiB；模板默认正文 16 MiB、可配置至 32 MiB；导出桥接 512 MiB/120 秒。超过 10 MiB 附件不列为提高上限的修复任务。

| 功能点 | 是否缺失 | 本地 port 自行执行 | 内核端点 / 已有桥接 | 需要关注的功能缺失、影响什么日常操作 | 测试情况 |

B1 指单次普通只读工具调用的累计预算：默认 128 次 API I/O、8 MiB 解码数据，分别可配置为 16–512 次、1–64 MiB；只读协作期限默认 30 秒，可配置 1–120 秒。read_image 在普通读取预算外增加 20 MiB 图片额度，单图仍限制 20 MiB。配置位于 mcpHttpSettings.kernelOptions，当前通过高级配置调整，参见 [配置说明](../zh/reference/kernel-options.md)。

B1 不是通用内存硬上限：它计量 scoped client 已返回的解码数据和调用次数；包括 requestResource.text/json/arrayBuffer 消费；不包括 Go 预缓冲、统计落盘、external/extension/App 会话路径，也不截断进入提交阶段的写入。某些 action 没有合适的游标时，需要缩小目标集合，而非简单增加页码。
